### Earlier voice and character implementation

- Pi `orion-listener` service owns stereo capture, Rustpotter, mono endpointing,
  bounded pre-roll/follow-up buffers and token-authenticated plain WebSocket port 7448.
- Rustpotter wrapper, native source and reference moved to `voice/`. Studio's
  dependency was removed and its lockfile updated; Pi gets its own uv lockfile.
- Studio has no workstation capture, AudioWorklet, wake detector or local
  speaker fallback. Its worker connects to the Pi and exposes protocol v5 to UI.
- Qwen must confirm the wake prefix before the agent receives command text.
  Paused follow-up speech is buffered while Qwen works. One random session ID
  correlates utterances, decisions and playback; stale messages are rejected.
- At the user's request, TLS was removed after the initial implementation.
  Studio derives ws://GATEWAY_HOST:7448/; ORION_PI_VOICE_URL can override it
  with another ws:// endpoint. Certificate flags and ORION_PI_VOICE_CA support
  are removed. The service requires the existing Studio token, not certificates.
  Audio and tokens travel unencrypted on the trusted LAN. The Pi token is
  inherited through the worker environment and reused from Studio's gateway
  connection. The later pairing follow-up saves it in the OS credential store
  after one manual entry, with automatic launch/outage reconnect.
- Character defaults on through the existing configure/enable/home sequence;
  `--character-on-start off` is the maintenance override. Studio Stop lasts for
  the current daemon session. Deployment smoke scripts handle the changed default.
- Authored attention_left/right use complete named absolute poses, existing
  expressive_turn style, approximately +/-0.35 rad final yaw, three through
  drawings and final settle. No calibration or global style was changed.
- Direction uses coarse stereo GCC-PHAT voting. Zero default geometry disables
  direction until measured spacing and orientation are supplied. Confidence
  below 0.75 or confirmation more than three seconds after the finalized
  observation suppresses a turn without suppressing command processing.
- Attention holds a temporary anchor, suppresses autonomous idles during the
  conversation, and restores the prior anchor 15 seconds after neutral.
- Setup, architecture, configuration and animation documentation updated.

## Bugs Fixed

- Follow-up deployment sudo failure: install scripts forced `sudo -n`, and
  SSH supplied the bootstrap on stdin with no terminal for a prompt. The early
  `sudo true` check did not establish that later privileged operations could
  execute. The exact failing sudo command/Pi policy could not be inspected:
  read-only SSH from this tool session failed authentication.
- Launcher now stages the current bootstrap with SSH/scp and executes through
  `ssh -t`. Scripts use `sudo -v` and normal sudo, preserving terminal prompts
  and existing authorization policy. System service inspection is unprivileged;
  only system service mutations use sudo. Installed apt prerequisites are
  detected with dpkg-query and skipped rather than reinstalled on every update.
- Launcher/installer/merge checks: 19 tests passed using isolated fixtures and
  Git repositories. Transfer/remote failures propagate and attempt tempfile
  cleanup. Actual Pi password prompting remains unverified from this session.
  Commit/push these changes before retrying: helpers are read after Pi merge.

- Cancelled/timed-out startup previously entered home idle: only completed
  homing now establishes that state and anchor.
- Follow-up speech during wake confirmation could be lost: Pi buffers a
  bounded endpointed follow-up while Studio confirms.
- An idle could delay the attention return: conversational attention now
  holds purposeful stillness until speech or return.
- Stop during a pending WAV upload could allow a later accepted run to play:
  a generation check now cancels that run when its acceptance arrives.
- An unexpected worker close could leave UI readiness stale: it now fails
  and releases the active pipeline and owned playback.

## Key Decisions & Why

- A dedicated Pi WebSocket isolates audio queues and latency from the
  synchronous gateway and 50 Hz motor loop. The Python processing worker is
  its client; Tauri passes connection configuration.
- Send a candidate immediately, then a complete endpointed utterance. This
  preserves the existing whole-utterance Qwen API and avoids continuous room
  audio transmission. Continuous live audio streaming was not introduced.
- Qwen confirmation precedes directional movement. Estimate direction during
  speech before motor movement and expire stale observations.
- Ordinary absolute motion assets establish facing; relative speech and idle
  continue to obey immutable-anchor semantics. No raw motor access added.
- Preserve legacy Sherpa/Moonshine/Piper as explicitly optional diagnostics,
  never start them alongside the primary microphone owner.

## Lessons Learned & Gotchas

The hardware HAT has two channels, but their physical independence, orientation
and acoustic quality are not established by requesting stereo. Coarse direction
is not full azimuth, front/back location or a calibrated probability. The
current energy endpoint thresholds came from Studio and need Pi evaluation.
Character Off does not mute the microphone. Capture opens only while an
authenticated Studio session has enabled it; loss of that session closes it.
There is no automatic replay or reconnect. Barge-in and AEC remain unimplemented.
